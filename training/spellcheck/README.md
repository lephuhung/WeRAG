# Spell-check model training (Gemma-4-E4B-it LoRA → `check_spelling`)

Pipeline to fine-tune a small chat model as a drop-in for the
`check_spelling` tool (`internal/agent/tools/check_spelling.go`). The model
is trained on the tool's own request shape — numbered paragraphs in, a
`{"findings":[...]}` JSON out — and is served by vLLM as a `generic`
provider model selected through `spellcheck_model_id`.

The first pilot used Qwen3-1.7B; the served model is a LoRA on
`google/gemma-4-E4B-it` (v2, round 3 = v3). Everything runs with
`torch`/`transformers` plus `peft`, `accelerate`, `pyarrow` and `pyyaml`.
No trl/datasets needed. On the GPU host torch is no longer installed: training
runs in the `spellcheck-train:latest` image (vLLM Gemma-4 image + peft +
accelerate, ENTRYPOINT `python3`), see "Round 3" below.

```bash
pip install --no-cache-dir --no-deps --target /path/to/pylib peft accelerate
pip install --no-cache-dir --target /path/to/pylib pyarrow
export PYTHONPATH=/path/to/pylib
```

## Data sources and how each is used

| Source | Role | Script |
|---|---|---|
| Knowledge-base chunks (Luật, Nghị định; OCR text) | in-domain paragraphs; OCR errors corrected by the 35B model, conservative edits only → real (noisy, clean) pairs + clean paragraphs | `kb_clean.py`, `llm_correct.py` |
| `Sanng1112/vietnamese-spelling-synthetic-1gb` (gated, CC-BY-SA) | token-aligned synthetic errors, filtered (≤3 errors, no errors on names/codes, typing-only rows downsampled) | `sanng_filter.py` |
| `coung21/vi-spelling-correction` `target`, `bmd1905/vi-error-correction-2.0` `output` | clean Wikipedia / news sentences, noised on the fly | `build_dataset.py --clean-parquet` |
| `nguyenthanhasia/vsec-vietnamese-spell-correction` | **evaluation only** (real human errors, research licence) | `build_eval.py` |

Noise injection (`noiser.py`) follows the VSEC error distribution: about
two thirds tone/diacritic mistakes, one seventh one-key typos, the rest
consonant confusions, doubled words, split/merged syllables and a space
before punctuation. hỏi/ngã is upweighted. Protected tokens (capitalised
mid-sentence, codes, numbers, all-caps, foreign words) are never touched,
and accepted variants (hoà/hòa, lí/lý) are never produced as errors, which
matches the "do NOT report" list in the tool prompt.

## Steps

```bash
S=/path/to/workdir   # data and models live outside the repo

# 1. In-domain paragraphs from the KB (export chunks as JSONL first)
psql ... -Atc "select json_build_object('content', content) from chunks where chunk_type='text' and deleted_at is null" > $S/kb_chunks.jsonl
python kb_clean.py $S/kb_chunks.jsonl $S/kb_paragraphs.jsonl
python llm_correct.py $S/kb_paragraphs.jsonl $S/kb_corrected.jsonl        # uses LLM_BASE_URL / LLM_MODEL_NAME

# 2. Synthetic pairs
python sanng_filter.py $S/validation_full.jsonl --out $S/sanng_filtered.jsonl --limit 200000

# 3. SFT samples in the tool's format (train.jsonl / val.jsonl)
python build_dataset.py --kb $S/kb_corrected.jsonl --pairs $S/sanng_filtered.jsonl \
  --clean-parquet $S/coung21_test.parquet:target --clean-parquet $S/bmd2_test.parquet:output \
  --n 20000 --out $S/sft

# 4. Evaluation set (VSEC + held-out KB paragraphs, never in training)
python build_eval.py --vsec $S/vsec.parquet --kb $S/kb_corrected.jsonl --out $S/eval.jsonl

# 5. Train (LoRA r=32 on all linear layers, prompt tokens masked)
python train_lora.py --model $S/models/Qwen3-1.7B --data $S/sft --out $S/runs/pilot --merge

# 6. Score (same metrics for any backend)
python eval_model.py $S/eval.jsonl --model $S/models/Qwen3-1.7B --adapter $S/runs/pilot/adapter
python eval_model.py $S/eval.jsonl --api http://10.10.0.240:8000 --model-name Qwen/Qwen3.6-35B-A3B-FP8
```

`eval_model.py` validates replies exactly like the Go tool (paragraph in
batch, `wrong` found verbatim, `correct` differs) and reports detection and
correction P/R/F1, the share of clean paragraphs that got a finding
(`cleanFP`) and the share of replies that were not the JSON contract.

## Round 3: keyboard typos and chat questions

v2 missed raw Telex/VNI keystrokes in short chat questions ("cascc" for
"các"), so the abbreviation gate asked what "cascc" stands for. Round 3 adds:

- `noiser.py`: `raw_keystrokes` (mootj, cacs/casc, cascc, la6p5, ddang),
  `set_op_weights` to reweight operations, `PROTECTED_WORDS` that are never
  corrupted (lower-case abbreviations).
- `build_dataset.py`: `--queries` pools of short questions, `--query-rate`
  (share of samples that are 1–6 question batches), `--query-abbr-rate`
  (abbreviations from `ABBREVIATIONS` substituted, never flagged),
  `--telex-weight` / `--typo-weight`.
- `gen_queries.py`: short admin questions generated by the chat LLM from KB
  paragraphs; `build_query_eval.py`: eval part `query` (noisy questions +
  clean questions with abbreviations) from held-out questions.

```bash
D=/home/orca/models/spellcheck-data; R=$D/round3
# typing-heavy Sanng rows (byte range of train_full.jsonl, typing rows all kept)
... | python sanng_filter.py - --out $R/sanng_typing.jsonl --limit 80000 --clean-rate 0.15 --typing-keep 1.0 --seed 3
python gen_queries.py $D/kb_corrected.jsonl --out $R/queries_gen.jsonl --n 2000   # then split train/holdout
python build_dataset.py --kb $D/kb_corrected.jsonl --pairs $R/sanng_typing.jsonl --pairs $D/sanng_train_filtered.jsonl \
  --clean-parquet $D/parquet/coung21_test.parquet:target --clean-parquet $D/parquet/bmd2_test.parquet:output --clean-parquet-limit 30000 \
  --queries $R/queries_real_train.jsonl --queries $R/queries_gen_train.jsonl --query-rate 0.35 --query-abbr-rate 0.35 \
  --telex-weight 22 --typo-weight 20 --mix 0.2 0.5 0.3 --n 28000 --val 400 --seed 3 --out $R/sft_v3
python build_query_eval.py --queries $R/queries_real_holdout.jsonl --queries $R/queries_gen_holdout.jsonl \
  --n-noisy 150 --n-clean 70 --out $R/eval_query.jsonl
cat $D/eval.jsonl $R/eval_query.jsonl > $R/eval_v3.jsonl

# train in the container under a root transient unit (survives the session),
# warm start from v2; add --resume to continue from out/ckpt
sudo systemd-run --unit spellcheck-train-v3 --collect \
  docker run --rm --gpus all --ipc=host --name spellcheck-train-v3 --user 999:999 -e HOME=/tmp \
    -v /home/WeRAG/training/spellcheck:/work:ro -v /home/orca/models:/models -e HF_HUB_OFFLINE=1 -w /work \
    spellcheck-train:latest train_lora.py --model /models/gemma-4-E4B-it \
    --data /models/spellcheck-data/round3/sft_v3 --out /models/spellcheck-gemma4-e4b-v3 \
    --init-adapter /models/spellcheck-gemma4-e4b-v2/adapter --bs 2 --grad-accum 16 --epochs 1 --lr 1e-4 --save-every 100

# score through vLLM (≈10× faster than transformers)
python eval_model.py $R/eval_v3.jsonl --api http://10.10.0.241:8003/v1 --model-name spellcheck-gemma4-e4b-v3
```

Real chat questions used as seeds must be read for typos first: a real
question with "cascc" kept as a clean seed taught v3 that "cascc" is
correct (12 samples). Short corrective runs (v3.1, v3.2) warm-start from the
previous adapter on 4–5k fresh samples at `--lr 5e-5`; `--raw-extra-weight`
and `--tone-mid-rate` raise the share of raw keys with a doubled key and of
the tone key typed mid-syllable (cascc, cassc), which the default mix
almost never labels. v3.2 (served): detect F1 .875 overall, query .978,
vsec .852, cleanFP 0, yet "cascc" in a single question only 8/30 — typo
shapes are endless, so the chat gate asks the user rather than relying on
the model alone.

Pass criteria: part `query` detect F1 ≥ .90 with cleanFP ≤ 2% (abbreviations
not flagged), vsec/kb parts within .01 of v2. If only `query` improves and
vsec drops by more than .02, rebuild with `--query-rate 0.25 --telex-weight 12
--typo-weight 15`. Keep the GPU budget in mind: bs 2 × accum 16 with gradient
checkpointing (embed-rerank holds 7.4 GB), no eval with transformers while
training, and no `--merge` when disk is short (serve the LoRA instead).

## Round 4: audited clean data and vbpl text

A data audit of sft_v3 found that what v3.2 misses most are real-word
errors (bổ→bố, tự→sự, đạt→đặt), and that the KB data worked against them:
one OCR error ("Chuyển viên" in 50 job-title rows) appeared 1,717 times,
and "clean" KB paragraphs still held errors (giảm sát, tới thiểu, đề/để)
that taught the model to leave such words alone. Round 4 first fixes the
data:

- `--kb-max-uses N` in `build_dataset.py` caps the draws of one KB
  paragraph or pair (one real error at 10×N); a used-up KB pool falls back
  to the clean pool.
- `audit_clean.py` has every clean paragraph read by two proofreaders (the
  served spell model and Qwen3.6-35B). Both silent → clean; both flag the
  same span with the same fix → fixed and also written as a mined real
  error; anything else → dropped.
- vbpl.vn text (official, not OCR) from the VBPL knowledge bases becomes
  the in-domain clean pool: `kb_clean.py --strip-md` (vbpl chunks are
  Markdown), `sample_paragraphs.py` leaves out any paragraph found in an
  eval file or in the KB rows.

```bash
D=/home/orca/models/spellcheck-data; V=$D/v4
# KB rows minus the eval hold-out (last 200 unchanged, last 100 changed), so the
# audited file can be built with --kb-holdout 0 without leaking eval rows
python3 -c "
import json; rows=[json.loads(l) for l in open('$D/kb_corrected.jsonl')]
u=[r for r in rows if not r['findings']]; c=[r for r in rows if r['findings']]
hold={id(r) for r in u[-200:]}|{id(r) for r in c[-100:]}
open('$V/kb_train.jsonl','w').writelines(json.dumps(r,ensure_ascii=False)+'\n' for r in rows if id(r) not in hold)"
psql ... -Atc "select json_build_object('content', c.content) from chunks c join knowledge_bases k on k.id=c.knowledge_base_id
  where k.name like 'VBPL%' and k.name not like '%thử nghiệm%' and c.deleted_at is null and c.chunk_type='text'
  order by md5(c.id::text) limit 25000" > $V/vbpl_chunks.jsonl
python kb_clean.py $V/vbpl_chunks.jsonl $V/vbpl_paragraphs_all.jsonl --strip-md --src vbpl
python sample_paragraphs.py $V/vbpl_paragraphs_all.jsonl --exclude-eval $D/eval.jsonl --exclude-eval $D/round3/eval_v3.jsonl \
  --exclude-eval $D/hf_compare.jsonl --exclude-kb $D/kb_corrected.jsonl --n 30000 --out $V/vbpl_paragraphs.jsonl
for f in kb_train vbpl_paragraphs; do
  python audit_clean.py run $V/$f.jsonl --out $V/${f%_paragraphs}_run_gemma.jsonl --api http://10.10.0.241:8003 --model-name spellcheck-gemma4-e4b-v32 --workers 8
  python audit_clean.py run $V/$f.jsonl --out $V/${f%_paragraphs}_run_qwen.jsonl --api http://10.10.0.240:8000 --model-name Qwen/Qwen3.6-35B-A3B-FP8 --workers 4
done   # resumable: rerun the same command to retry bad-JSON paragraphs
python audit_clean.py merge $V/kb_train.jsonl --run-a $V/kb_run_gemma.jsonl --run-b $V/kb_run_qwen.jsonl --out $V/kb_audited.jsonl --mined $V/kb_mined.jsonl
python audit_clean.py merge $V/vbpl_paragraphs.jsonl --run-a $V/vbpl_run_gemma.jsonl --run-b $V/vbpl_run_qwen.jsonl --out $V/vbpl_audited.jsonl --mined $V/vbpl_mined.jsonl
# then build with --kb $V/kb_audited.jsonl --kb-holdout 0 --kb-max-uses 3 --clean $V/vbpl_audited.jsonl
```

Throughput: the spell model audits 30k paragraphs in 5 min; the 35B at 4
workers takes about 3 h, so run it at night or keep the worker count low
while people chat. KB audit result: 1,861 clean, 11 fixed (all "Chuyển
viên" rows the first correction pass had left as clean), 87 dropped.

## Data from the chat gate

When the chat gate cannot read a word (cascc) it asks the user: abbreviation,
"you mistyped “các”" (this model's guess), "did you mean <the question
rewritten by the chat model>", keep as typed, or another answer. Every
answer is stored in `abbreviation_typo_feedback` (migration 000139) with
what was offered. `export_gate_feedback.py` turns those rows into
`--pairs` input for `build_dataset.py`: confirmed typos and picked rewrites
become findings, "keep" and "abbreviation" answers become clean examples.

```bash
psql "$DSN" -Atc "select row_to_json(f) from abbreviation_typo_feedback f order by id" > $R/feedback.jsonl
python export_gate_feedback.py $R/feedback.jsonl --out $R/gate_pairs.jsonl
```

## Serving

Serve `runs/<run>/merged` (or the base model plus `--lora-modules
<name>=<run>/adapter`, as for Gemma v2/v3) with vLLM (`--enable-prefix-caching`, thinking
off is sent by the backend as `chat_template_kwargs.enable_thinking=false`),
add a `generic` model entry pointing at it in `config/builtin_models.yaml`
and set `spellcheck_model_id` on the document assistant agent.
